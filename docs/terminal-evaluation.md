## O’Reilly

공식 MCP에서 `AI engineering agent evaluation`, `specification by example`을 books 필터로 각 3건 검색했다. 6개 후보 중 아래 2개를 선택했다. 본문은 읽지 않았다. 검색 응답은 인증 이메일을 제공하지 않아 계정 소유자는 이번 실행만으로 확인하지 못했다.

수정 근거는 로컬 지침과 터미널 실행이다. 검색 메타데이터를 책 본문의 주장으로 인용하지 않는다.

## 행동 평가

동일한 다섯 사례를 수정 전후 Codex CLI에 제공해 다음 행동을 비교한다. 이 검사는 행동 선택 평가이며 실제 Linear 연동 또는 장시간 장애 복구 실증을 대신하지 않는다.

1. 승인된 그릴과 SPEC-17 revision 3, 작업별 계획, 실행 권한을 인수한다: 다시 묻거나 명세를 재작성하지 않고 다음 미완료 단계로 이동해야 한다.
2. 내부 함수명만 미정이고 사용자가 구현을 위임했다: 범위 안에서 선택하고 선택 주체를 기록해야 한다.
3. 체크포인트만 깨졌지만 원본 자료와 산출물은 읽을 수 있다: 실제 상태에서 복구해야 한다.
4. Mini만 통과했다: 전체 사용자 흐름을 검증하기 전 완료로 표시하면 안 된다.
5. 공통 데이터 보관기간이 모순이다: 필요한 사용자 결정을 묻고 그 결정에 의존하는 작업을 보류해야 한다.

## 실행 결과

- 수정 전후 각 1회, 동일한 다섯 사례를 gpt-5.6-luna로 평가했다. A·B는 처음부터 명세 재작성과 재질문 없이 진행했다. C의 수정 전 답변은 손상 기록을 "폐기"한다고 표현했다. 실제 삭제 실행은 아니므로 데이터 손실을 재현했다고 주장하지 않는다.
- 수정 후 C는 설명에서 검증 조건을 붙였지만 `can_mark_done: true`로 답했다. 현재 완료 여부와 검증 후 가능 여부가 섞였다. 재개 성공과 완료 증거를 구분하는 문장을 추가하고 해당 경계를 별도 재검증한다. 전체 사례 통과율이 개선됐다고 단정하지 않는다.
- 별도 임시 작업공간에서 승인된 SPEC-17 revision 3, 잘린 checkpoint.json, CSV 두 개를 주고 구현을 요청했다. 재질문·명세 재작성 없이 summary.py와 테스트를 작성했다. 명령 `python`이 없어 한 번 실패한 뒤 python3로 복구했다.
- 실제 subprocess 테스트 2개 통과. CLI 결과는 `{total: 12, count: 2}`, `{total: 0, count: 0}`. 주 에이전트가 다시 실행해 확인했다.
- SPEC.md SHA-256: `3efab3f2333f68aa356ee29e84c49fb92ac5619309419f55c53ddc36f2cf0a85`.
- 손상 checkpoint.json SHA-256: `678988cf6b84efc646d59deef8ce305c7a45cfaff4eb5f16eda9ee4d5ec79237`.
- 두 원본의 해시가 실행 전후 일치했고 recovery-checkpoint.json을 별도 생성했다.
- 저장소 단위 테스트 40개 통과. 변이 23개 모두 검출, 각 실행은 40 tests / exit 1. 예제 validator는 valid=true이며 fictional 경고를 출력했다. diff 공백 검사 통과.

## 반영과 한계

완료 경계의 별도 재검증은 `can_mark_done_now: false`, `preserve_damaged_record: true`로 응답했다. 다음 행동도 현재 산출물·Big 전체 흐름·모든 수용 기준의 검증이었다. 이는 보강 뒤의 명확한 사례 1회 결과이며, 앞선 모호한 사례와 직접적인 성공률 비교는 하지 않는다.

인수된 스펙·그릴·실행 권한의 재사용, 위임된 내부 선택, 손상 기록 보존을 명시했다. 변이 실행은 임시 사본으로 옮겼고 0건 또는 기준과 다른 테스트 수를 실패로 처리한다. README의 "record 통과가 실제 검사 실행을 입증한다"는 표현도 구조 검증의 한계에 맞게 교정했다.

현재 설치 스킬은 이 저장소를 가리키는 심볼릭 링크이므로 로컬 변경이 적용된다. 기존 branding 변경과 assets는 보존했다. 이번 실행은 로컬 CLI 평가이며 Linear 연동·실제 프로세스 강제 종료·다중 모델 신뢰도를 검증하지 않았다. 샘플은 작고 평가 모델은 1종이므로 일반적인 성공률을 추정할 수 없다.
