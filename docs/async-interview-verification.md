# 비동기 인터뷰 질문 수명 검증 — 2026-09-14

## 문제와 수정

비동기 질문 도구 호출 직후 최종 답변으로 턴을 종료하면, 진행 중인 턴에서만 제공되는 질문 UI를 사용자가 답하기 전에 닫을 수 있다. 기존 인터뷰의 무조건적인 턴 종료 지시를 도구 계약별 대기로 바꿨다. 질문 1개, 미응답 시 진행 금지, 기존 답변 재사용 원칙은 유지한다.

## 근거와 읽은 범위

- [OpenAI 스킬 공식 문서](https://learn.chatgpt.com/docs/build-skills): SKILL.md, 보조 자료, 도구 의존성과 테스트 지침을 읽었다.
- [Claude Code 스킬 공식 문서](https://code.claude.com/docs/en/skills): 도구 허용/제외 설정을 확인했다. 공통 스킬 형식이 동일한 질문 UI 수명을 보장하지 않는다.
- 현재 호스트의 실제 도구 계약: request_user_input은 Plan 모드 제한, request_user_input_async는 즉시 반환하고 사용자 메시지가 비동기로 도착한다. wait의 시간 경과는 답변이 아니다.
- 설치된 데스크톱 앱 코드 읽기: 비동기 질문 패널은 턴 상태가 inProgress가 아니면 렌더링하지 않고, 질문 표시 상태는 message로 분기한다. 이 대화의 호출은 앱 알림 로그에 접수됐다. 사용자가 평문 표시를 보고했다. 순간 표시 여부와 다른 버전 동작은 미검증이다.
- O’Reilly 검색: `AI agents human in the loop asynchronous`, books 3건. 주 후보는 Michael Albada, *Building Applications with AI Agents* (2025-09-17), [링크](https://learning.oreilly.com/library/view/-/9781098176495/). 메타데이터만 확인했으며 본문은 읽지 않았다. 책을 UI 동작의 근거로 사용하지 않았다.

## 검증과 한계

- 저장소 unittest 40개 통과. 기존 기록 검증기의 회귀 검사이며 질문 UI 동작 증거는 아니다.
- 예제 completion.json은 validator가 수락했다. fictional 경고는 유지되며 실제 완료 증거가 아니다.
- 인터뷰·진입점·README·방법 설명에서 현재 절차의 무조건적 턴 종료 지시를 제거했다. 과거 release-status는 당시 이력으로 보존한다.
- 검토: blocking 도구는 반환 답변 사용, async는 한 번 호출 후 최종 답변 없이 interruptible wait, 불가 시 평문+턴 종료. 빈 응답·기본 선택·접수·시간 경과는 결정으로 기록하지 않는다. 취소·정정은 먼저 처리한다.
- 실제 사용자 질문 UI 표시와 선택 응답 수신은 별도 실검증 필요. 문서 검사나 기존 테스트 통과만으로 UI 해결을 선언하지 않는다.

## 실검증 절차

1. 허용된 구조화 질문 도구로 한 질문과 선택지를 보낸다.
2. 비동기 반환이면 최종 답변을 보내지 않고 호스트의 interruptible wait를 60초 이하 단위로 사용한다.
3. 사용자가 선택지 표시 여부를 답하면, 실제 수신한 내용을 기록한다. 답변 전 다음 제품 질문·명세·구현으로 진행하지 않는다.
4. 보이지 않는다는 답이면 해결로 표시하지 않고 현재 앱 상태·기능 제공 조건을 추가 확인한다. 자동 재질문과 권한 우회는 하지 않는다.
